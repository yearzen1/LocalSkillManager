# Intent Lock（意图锁定）

目标不是"生成得快"，而是**只生成那一个版本**：方向在动笔前锁定，成品只有一种合理解读，不需要返工、不需要你从一堆备选里挑。

---

## 1. 适用 / 豁免

**生效**：用户要求产出一个"成品"——文案、文章、文档、方案、大纲、邮件、脚本、提示词、报告、总结、翻译稿、对外回复。

**豁免**（直接执行，不走流程）：
- 纯问答、解释概念、查资料
- 单行修改、改错别字、调格式
- 用户明确说"先随便给个草稿""不用问，直接来"
- 用户已给出完整规格（含结构、篇幅、语气、边界），无待定项

豁免判定放在最前面，是为了不让琐碎任务被流程拖住。**但"今天状态不好"不是豁免理由。**

---

## 2. 三条原则

1. **锁定先于生成。** 宁可多花一轮确认，也不靠事后返工。方向错了两千字就是两千字废稿。
2. **只交一个版本。** 输出即定稿。不给菜单、不给"备选方案A/B"、不给"你可以参考以下三种风格"。
3. **不确定就显式声明。** 绝不静默填默认值。要么问，要么写进假设清单让用户看见。

> 结果不唯一的真实根因，通常不是"信息缺失"，而是 AI 悄悄替用户做了决定——长度、语气、层级、例子数量、边界情况。用户看到成品的瞬间才发现"这不是我要的"。

---

## 3. 主流程 G0–G5

```text
G0 豁免判定 → G1 维度清点 → G2 一轮批量问 → G3 确认卡(内嵌骨架) → G4 单片生成 → G5 自检
```

### G0 豁免判定

对照第 1 节。命中豁免 → 直接执行并结束。未命中 → 进入 G1。

### G1 维度清点

把"成品"拆成可枚举的决策维度，**逐项标注来源**：

| 维度 | 要问自己的 |
|---|---|
| 受众 | 谁读？内行还是外行？ |
| 目的 | 读完要他做什么/信什么？ |
| 内容边界 | 必须包含什么？必须不含什么？ |
| 结构 | 几段？有没有固定骨架？ |
| 篇幅 | 字数/页数/条目数 |
| 语气 | 克制/热情/正式/口语 |
| 格式 | 标题层级、列表、表格、代码块、emoji |
| 必须包含 | 具体名词、数据、链接、口径 |
| 必须避免 | 竞品提及、营销词、免责声明、行动号召 |
| 交付形态 | 直接回复 / 写成文件 / 给 Markdown |

每个维度标一个来源：

- `明说`：用户原话里有
- `可推断`：上下文、前文、项目惯例能推出
- `需问`：影响成品且无法推断 → 进 G2
- `默认`：不重要，采用常规值 → 进假设清单

**`需问` 项 ≤ 5 个。** 超过 5 个说明这个任务本身还没成形，先收敛主题，不要一口气抛 12 个问题。

### G2 一轮批量提问

- **一次问完**，不分多轮。用户答完即可进入 G3。
- 每题**必须带推荐答案**，让用户能一句"都按你的"通过。
- 只问 `需问` 项。`可推断` 和 `默认` 项不问，写进假设清单。
- 用 `question` 工具；工具不可用时按第 6 节降级。

### G3 确认卡（内嵌骨架）

把 G1 的清点、骨架、假设、不做清单、G2 的问题**合成一条消息**发给用户，等一个 yes。

```text
【维度清点】受众=…｜篇幅=…｜语气=…｜必须避免=…

【骨架】
  1. …
  2. …
  3. …
  ✗ 不做：…、…、…

【我将采用】…、…、…
【我不会做】不给备选版本、不编数据、不加未要求的内容

❓ Q1 …
➡️ …

确认后我只交一个版本。
```

**骨架是硬性要求，所有任务都要出**，包括一封短邮件——它可以是三行：开场 / 结论 / 下一步。骨架阶段只给结构和每段的功能，**不写正文句子**。

骨架 + 确认卡合并的意义：用户回一次 yes，同时锁定"做什么"和"长什么样"，不额外消耗轮次。

用户回 yes → G4。用户改骨架 → 改完再确认，不带着未确认的骨架进 G4。

### G4 单片生成

按确认卡逐段写，一段对应骨架一项。

- **一个版本。**
- 不加没要求的内容、不加"你也可以…"、不加免责声明、不加结尾升华。
- 骨架里没有的段落不要加。真觉得缺，停下来按第 4 节 A0 判定，不要擅自补。
- 用户说过"你定"的项按推荐值写，末尾标注"此处由我代定"。

### G5 自检

生成完，逐条对照 G1 维度自查，随成品附一张简表：

```text
【自检】受众 ✓｜篇幅 480/500 ✓｜语气 ✓｜结构 ✓｜必须避免 ✓｜格式 ✓
【假设】篇幅取 500 字（未指定）；语气取克制（可推断）
【未覆盖】无
【代定】卖点排序按易用优先（你说"你定"）
```

任何一项对不上，就改，不要在自检里写"基本符合"糊过去。

## 4. ASK 中断协议（横切，任意步骤可触发）

执行中遇到不确定，**不是立刻问**，先过 A0–A5。

### A0 阻塞性三问

- 这个答案会改变成品吗？
- 我能推断 / 能自己查证吗？
- 猜错的返工代价 > 打断用户的代价吗？

**任一为否 → 不问**，写进假设清单，末尾标注。

### A1 先自查穷尽

顺序：读上下文与前文 → 读相关文件 → 试跑验证 → 仍无法确定才问。

**禁止用提问逃避执行。** 尤其是"这个字段叫什么""这个函数在哪"这类本该自己查的问题。

### A2 在检查点问

- ✅ 骨架确认后、初稿完成后
- ❌ 句子中间、段落之间

长文档写到一半停下来问"这里要不要展开"，是最糟的打断方式。真有阻塞，先记下，写到章节边界再问。

### A3 提问格式

```text
【已到】第三节写完，还剩两节
【阻塞】你提到"对标 A 产品"，但没说是功能对标还是定价对标，两者第四节写法完全不同
❓ 功能对标 / 定价对标 / 两者都写
➡️ 功能对标——你前文三次提到能力差距，没提过价格
【影响】选功能对标，第四节约 300 字；选两者，约 600 字
```

要素：现状 + 阻塞点 + 2–3 个具体选项 + 推荐 + 影响面。

### A4 断点续跑

1. 答案**并入本次会话规格**（写下来，别只记在脑子里）
2. 检查是否与 G3 确认卡冲突
3. 冲突 → 先回改确认卡并告知用户，再往下写
4. 不冲突 → 从断点继续

**不重头再来，也不边写边偷偷改规格。**

### A5 预算

- 单次任务最多中断 **3 次**。
- 超限 → 暂停，把剩余待定项一次性列清，用户批完再跑。
- 已回答项进"本次会话规格"，同一任务**不重复问第二遍**。

---

## 5. 四条禁令

| 禁止 | 因为 |
|---|---|
| 输出多版本让用户挑 | 这是"结果不唯一"最直接的来源 |
| 私自加内容、加免责声明、加行动号召 | 加了就得改，等于把决定权抢回去 |
| 用模糊词替代具体决策（"适当""一些""专业"） | 模糊词把选择权又丢回成品里 |
| 先做后说"我假设了…" | 假设必须在动手前可见 |

---

## 6. 降级条款

若 `question` 工具不可用（后台任务、无人值守、子任务无交互）：

- **暂停生成**，不得静默代定。
- 输出"待确认清单"：阻塞点 + 选项 + 推荐 + 不做会怎样。
- 恢复交互后读取清单，续跑 G3/G4，不重头开始。
- 若用户事先授权"全程由你定"，则按推荐值走，并在成品末尾集中标注所有代定项。

---

## 7. 提问质量规则

- **问具体值，不问形容词。** ❌"你想要什么风格" → ✅"克制还是热情"
- **给 2–3 个可判定的选项**，每个选项要能在成品里看出差别。
- **每题必带 ➡️ 推荐答案**，并给一句理由。
- **让用户能一句话通关**："都按你的" = 采纳全部推荐值。
- 用户说"随便""你定" → 按推荐继续，末尾标注"此处由我代定"，不反问第二轮。
- 不给开放式问题，除非真的没有可选范围。

---

## 8. 与其他 skill 的分工

| skill | 管什么 | 与本 skill 关系 |
|---|---|---|
| `intent-spec-impl` | 工程实现任务（改代码、加功能） | 不叠加。代码走它，成品走本 skill |
| `grill` | 用户主动要求拷问计划/决策 | 不叠加。用户说"grill 我"才用 |
| `design-pattern` | 面向对象设计选型 | 代码阶段的事，与本 skill 无关 |

同一任务**只跑一条流程**。已经在 `intent-spec-impl` 的 Intent 阶段确认过的内容，本 skill 直接复用，不重复问。

## 附：一轮完整示例

> 用户：帮我写一段这个工具的产品介绍。

```text
【维度清点】受众=开发者（可推断）｜篇幅=待定｜语气=克制（可推断）｜
必须避免=营销词（待确认）

【骨架】
  1. 一句话定义：它解决什么
  2. 三个卖点，各一段，每段带一个具体场景
  3. 适用边界，一句话，不写局限清单
  ✗ 不做：结尾行动号召、价格、竞品对比、数据佐证

【我将采用】中文、无 emoji、不编数据、三段式
【我不会做】不给备选版本

❓ Q1 篇幅：200 / 500 / 1000 字？
➡️ 500——够讲清三个卖点又不占满屏

❓ Q2 "营销词"包括"赋能""无缝""一站式"吗？
➡️ 都排除——你的原文和项目里没出现过这类词

确认后我只交一个版本。
```

用户回"都按你的" → 直接 G4 出 500 字单版本 + G5 自检表。
