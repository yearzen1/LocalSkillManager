# Explanation 解释模板

理解导向、认知导向。读者想知道「为什么」，不急着动手。

## 骨架

```markdown
# 为什么 <某设计/现象>

一句话点明要解释的问题。

## 背景

- 问题从哪来
- 读者需要的前置概念

## 核心机制

- 关键概念及其关系
- 可用图、类比、数据流

## 为什么这样设计

- 目标与约束
- 与其他方案的对比

## 取舍

- 代价是什么
- 什么场景下不适用

## 延伸阅读

- 相关教程 / 指南 / 参考的链接
```

## 写作要点

- 围绕一个「为什么」展开，不写成百科。
- 允许观点和判断，但要给出理由。
- 用对比讲清取舍：方案 A vs 方案 B，各自代价。
- 不写操作步骤；需要动手时链接到指南。
- 图优于长段落：数据流、时序、层级各一张即可。

## 最小示例

```markdown
# 为什么报告渲染采用两阶段流水线

## 背景

报告需要同时支持 CSV 与 API 数据源。单阶段渲染会把解析和排版耦合在一起。

## 核心机制

第一阶段把任意数据源归一化为行列表；第二阶段只负责把行列表渲染为 HTML。

    数据源 → 归一化 → 行列表 → 渲染 → HTML

## 为什么这样设计

- 新增数据源只需实现归一化，不动渲染。
- 渲染可以独立测试，输入是稳定的行列表。

## 取舍

- 多一次内存拷贝，超大文件需要流式改造。
- 归一化层需要维护统一 schema。

## 延伸阅读

- 上手：用 CLI 生成第一份报告
- 任务：如何自定义报告主题
- 查证：`report` 命令参考
```

- [ ] 结尾链接到其他象限
