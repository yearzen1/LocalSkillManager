# Reference 参考模板

信息导向、认知导向。读者在查证，需要准确、完整、可扫描。

## 骨架

```markdown
# <模块/命令/API> 参考

一句话说明它是什么、解决什么。

## 签名 / 结构

    <signature 或配置结构>

## 参数

| 名称 | 类型 | 默认值 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | - | 是 | ... |

## 返回值 / 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |

## 错误

| 错误码 | 触发条件 | 处理 |
| --- | --- | --- |

## 约束

- 取值范围、互斥关系、版本差异

## 示例

最小可用示例，不展开教学。
```

## 写作要点

- 与代码/配置一一对应，字段顺序稳定。
- 默认值、必填、类型、取值范围一个都不能少。
- 只陈述事实；建议、推荐、取舍放到解释文档。
- 可扫描优先：表格 > 列表 > 段落。
- 版本差异单列一节，不混进正文。

## 最小示例

```markdown
# `report` 命令参考

把数据文件渲染为 HTML 报告。

## 签名

    report <input> [options]

## 参数

| 名称 | 类型 | 默认值 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `input` | string | - | 是 | 输入文件路径，支持 csv/tsv |
| `--out` | string | `report.html` | 否 | 输出文件路径 |
| `--theme` | string | `light` | 否 | 主题，可选 `light` / `dark` |

## 返回值

成功时退出码 `0`，失败时非 `0` 并向 stderr 写错误信息。

## 错误

| 错误码 | 触发条件 |
| --- | --- |
| `E_INPUT` | 输入文件不存在或不可读 |
| `E_FORMAT` | 文件扩展名不受支持 |

## 示例

    report scores.csv --out out.html
```

## 自检

- [ ] 每个字段都有类型、默认值、必填
- [ ] 无主观建议
- [ ] 与当前实现一致
- [ ] 表格可快速定位
